# Order status compare-and-set lesson

This course follows a bounded CRUD correction in buildecom, a marketplace application. The production path is [`src/server/orders/service.ts`](../src/server/orders/service.ts), specifically `updateOrderStatus`. The original source is preserved in [`snapshots/src-server-orders-service.ts.before`](snapshots/src-server-orders-service.ts.before). The action reads an order, checks seller scope and the legal state transition, then updates the order, creates an order event and audit row in a transaction, and notifies the buyer. The defect was that the final update identified the row by `id` alone. A second request could change the order after the first read, allowing stale validation to precede a new status write.

The staged repair keeps the existing policy and transaction shape. It adds the read status to the Prisma extended unique predicate: `{ id: input.orderId, status: order.status }`. A successful `update` returns the committed order and the existing event, audit, and notification behavior continues. If no row matches, Prisma raises `P2025`; the service maps that known conflict to `ORDER_STATUS_CHANGED` with HTTP status 409 before creating audit data or notifying the buyer. Other persistence errors remain failures, so infrastructure incidents are not mislabeled as ordinary conflicts.

Run the portable check from this project with `node --experimental-vm-modules --test tests/runtime-order-status.test.mjs`. The test imports the actual TypeScript service through [`tests/helpers-load-typescript.mjs`](../tests/helpers-load-typescript.mjs), and loads the real order policy and ApiError class while supplying explicit repository, notification, payment and unused Zod-error contracts. Its six cases cover accepted admin and in-scope seller transitions, stale conflict, seller ownership denial, real-policy rejection and unrelated persistence rethrow. It does not claim live Prisma or transaction isolation coverage. The remaining chapters map the request, explain compare-and-set, show the exact before/after, teach debugging, and provide exercises with separate solutions.
